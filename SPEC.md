# Widgee

## Цель и контекст

Open-source приложение для macOS, которое показывает на рабочем столе виджеты в стиле Apple. Виджеты настраиваются через UI. Сторонние виджеты пишутся на JavaScript/TypeScript поверх SDK с готовыми компонентами (бары, часы, графики) и доступом к системным метрикам.

Критерии успеха MVP:
- Приложение ставится из `.dmg` и живёт в menu bar.
- Три встроенных виджета (системный монитор, погода, часы) работают и настраиваются.
- Сторонний виджет можно написать по шаблону, он перезагружается на лету и виден на рабочем столе.
- Приложение в простое с тремя виджетами потребляет меньше 1% CPU и около 100 MB RAM.

## Границы (входит / не входит)

Входит:
- Приложение для macOS 26+ на Swift и SwiftUI, лицензия GPL-3.0.
- Виджеты как отдельные безрамочные окна на уровне рабочего стола.
- Режим редактирования: перемещение и изменение размера.
- Кастомизация фона и оформления через UI.
- JS SDK, песочница, система permissions.
- Встроенные виджеты: системный монитор, погода, часы (цифровые и аналоговые).
- Тулинг для авторов: hot reload, консоль ошибок, `.d.ts`, шаблон.
- Сборка `.dmg` в GitHub Actions, публикация в Releases.

Не входит в MVP:
- Каталог или магазин виджетов.
- Интерактивность (кнопки, ввод). Клик может только открыть URL.
- Локализация (только en).
- Интеграция со Stage Manager и экраном блокировки.
- Календарь и EventKit.
- Нативные WidgetKit-виджеты Notification Center.
- Автообновление приложения.

## Пользовательские сценарии

1. **Установка.** Пользователь открывает `.dmg`, переносит приложение в `/Applications`, запускает. Без подписи Gatekeeper предупредит, поэтому в README есть инструкция (правый клик → Открыть, либо `xattr -cr`).
2. **Добавление виджета.** Иконка в menu bar → галерея → выбор виджета и размера → виджет появляется на рабочем столе.
3. **Редактирование.** Режим редактирования включается из menu bar. Виджеты можно двигать и менять размер. Для каждого есть панель настроек: фон, радиус углов, шрифт, акцентный цвет и собственные `settings` виджета.
4. **Автор виджета.** Создаёт виджет из шаблона командой «новый виджет», правит `widget.js` и сразу видит результат (hot reload). Ошибки показываются в окне консоли.
5. **Установка стороннего виджета.** Положить папку в `~/Library/Application Support/Widgee/Widgets/` или импортировать `.widget` (zip). При установке приложение показывает запрашиваемые permissions.
6. **Сбой виджета.** Виджет показывает плашку «виджет упал» с кнопкой перезапуска. Остальные не затронуты.
7. **Виджет через ИИ-агента.** Во вкладке «Создать виджет» пользователь описывает, что хочет. Ниже сразу появляется готовый промт для ИИ-агента (Claude Code, Cursor и т. п.) с подставленной папкой виджетов и описанием. Пользователь копирует промт кнопкой, отдаёт своему агенту, агент создаёт папку виджета, и тот сам появляется в галерее (hot reload).
8. **Обновление приложения.** Приложение проверяет GitHub Releases и показывает ссылку на скачивание новой версии.

## Техническое решение

### Архитектура

- **Xcode-проект** (оболочка приложения, ресурсы, entitlements, иконки) и **SwiftPM-модули** (тестируемое ядро):
  - `WidgetHost` — загрузка манифестов, жизненный цикл JSContext, таймеры, hot reload.
  - `WidgetSDK` — API, доступное из JS, и `.d.ts` типы.
  - `Metrics` — сбор системных метрик.
  - `Renderer` — преобразование дерева компонентов в SwiftUI.
  - `Background` — протокол `BackgroundRenderer`. В MVP одна реализация на `glassEffect`, `GlassEffectContainer` и обычные заливки.
- **Лёгкий фон на старых системах.** Всё, что зависит от API macOS 26, изолировано в слое `Background`. Deployment target в MVP — 26. Остальной код не использует API новее macOS 14 (SwiftUI, JavaScriptCore, Swift Charts, host_statistics, IOKit). Это позволит добавить fallback на `NSVisualEffectView` и материалы для macOS 14+ без переписывания.
- Окна: `NSWindow` без рамки на уровне рабочего стола, видны на всех Spaces, под окнами приложений.
- Каждый виджет — отдельный `JSContext`.

### Модульная система и типы

- Код виджета — только ES Modules. CommonJS не поддерживается.
- Хост даёт встроенный виртуальный модуль `"widgee"` (через `JSScript` типа module и `JSModuleLoaderDelegate`). Разрешены импорты `"widgee"` и относительные файлы внутри папки виджета, остальные отклоняются.
- Типы: пакет `@widgee/sdk` с `index.d.ts` (`export declare function ...`). Шаблон содержит готовый скрипт сборки на `esbuild`, хост читает собранный `widget.js`.
- Первая задача этапа 2 — спайк загрузки модулей. Запасной вариант, если он провалится: глобальное API `widgee.*` без `import` с теми же типами как ambient-декларациями.

### Формат виджета

Папка (или `.widget` zip):

```
my-widget/
  manifest.json
  widget.js
```

`manifest.json` содержит:
- `id`, `name`, `version`, `author`;
- `sizes` (S/M/L/XL и допустимый диапазон свободного resize);
- `permissions`: `system` (список метрик) и `network` (allowlist доменов);
- `settings`: типизированные поля, по которым приложение рисует форму настроек.

### JS API (контракт)

- `render(ctx)` возвращает дерево компонентов. Контекст содержит `ctx.size`, `ctx.theme`, `ctx.settings`, `ctx.data`.
- Подписки объявляются декларативно: `defineWidget({ sources: { cpu: system("cpu", {interval: 2}), now: timer(1), w: http(url, {every: 600}) }, render(ctx) { ctx.data.cpu } })`. `sources` может быть функцией `(settings) => ({...})`: хост вызывает её при загрузке и при смене settings, пересоздаёт источники и сбрасывает данные. Тип поля settings `city` — объект `{name, latitude, longitude, country?}`; `select` принимает `options`. Хост сам ведёт опрос, перерисовывает виджет при новых данных и приостанавливает опрос, когда виджет скрыт или экран спит. До первого значения `ctx.data[key]` равен `null`. `system` требует метрику в `permissions.system`, `http` — только https и домен из `permissions.network` (хост выполняет запрос, не JS).
- JS не получает сырой `fetch`, `setInterval`, файлы и shell. Сеть идёт только через `useFetch` с проверкой allowlist.
- Компоненты:
  - разметка: `VStack`, `HStack`, `ZStack`, `Spacer`, `Text`, `Image` (SF Symbols);
  - бары: линейный, кольцо, gauge (полукруг), сегментный;
  - графики: sparkline, line/area, bar (Swift Charts), история метрик хранится в кольцевом буфере на стороне хоста;
  - часы: цифровые стили и аналоговый циферблат.
- Клик по виджету может только открывать URL.

### Метрики

| Метрика | Источник |
|---|---|
| CPU (общая, по ядрам) | `host_processor_info` |
| RAM (used/wired/compressed/swap) | `host_statistics64`, sysctl |
| Диск (объём, свободно) | `statfs` / `URLResourceValues` |
| Сеть ↑/↓ | `getifaddrs` |
| Батарея | IOKit |
| Топ процессов | libproc (без root виден неполный список) |
| Температура, вентиляторы, GPU | IOHID / IOAccelerator, best-effort, значение `null` при недоступности, помечено experimental |

### Оформление и кастомизация

- Фон: Liquid Glass, прозрачный, цвет, тонировка (цветной пикер и ползунок непрозрачности).
- Размеры S/M/L/XL и свободный resize.
- Радиус углов, шрифт (SF Pro / Rounded / Mono), акцентный цвет.
- Все настройки хранятся в конфигурации приложения по ID экземпляра виджета.

### Хранение

- Конфигурация (экземпляры виджетов, позиции, настройки) — JSON в `~/Library/Application Support/Widgee/`.
- Позиции привязаны к ID монитора плюс относительные координаты. Если монитора нет, виджет переезжает на главный и возвращается, когда монитор подключён снова.

### Встроенные виджеты

Все три написаны на JS через тот же SDK. Они же служат примерами для авторов.
- **Системный монитор:** CPU, RAM, диск, сеть, батарея. Разные стили баров и графиков.
- **Погода:** Open-Meteo без ключа. Город выбирается через поиск (геокодинг Open-Meteo). Опционально «текущая позиция» через Core Location, запрос только после включения пользователем.
- **Часы:** цифровые и аналоговые, выбор часового пояса, 12/24 ч, секунды.

### Генератор промта для ИИ-агента

Вкладка «Создать виджет» содержит поле «Что вы хотите видеть в виджете?» и блок с готовым промтом под ним.

- Промт собирается из одного шаблона `AGENT_PROMPT.md` (ресурс приложения) с плейсхолдерами `{{WIDGETS_DIR}}`, `{{USER_REQUEST}}`, `{{SDK_VERSION}}`. Подстановка происходит на лету при вводе. Кнопка «Скопировать».
- Шаблон самодостаточен, агенту не нужен доступ к репозиторию Widgee. Он содержит:
  1. задачу и описание пользователя;
  2. абсолютный путь папки виджетов и правило «создай подпапку `<id>` с `manifest.json` и `widget.js`»;
  3. формат манифеста с примером (id в kebab-case, версии SemVer, `sdk` = текущая версия, `permissions`, `settings`);
  4. правила кода: только ES Modules, импорт только из `"widgee"`, без файлов, сети, shell, `setTimeout` и `setInterval`, данные только через `sources` (`system`, `timer`, `http`);
  5. справочник компонентов и метрик (генерируется из тех же исходников, что `COMPONENTS.md` и `.d.ts`, чтобы не расходился с SDK);
  6. правила permissions: запрашивать минимально необходимое, домены только по необходимости;
  7. требования к виду: адаптация под `ctx.size`, использование `ctx.theme` (акцентный цвет, шрифт), обработка `null` в метриках;
  8. готовый минимальный пример виджета;
  9. порядок проверки: после записи файлов виджет появляется в приложении сам, ошибки смотреть в консоли Widgee, при ошибке исправить и повторить.
- Крайние случаи:
  - пустое описание: промт показывается с подсказкой, кнопка копирования неактивна;
  - путь с пробелами и не-ASCII символами подставляется как есть и в кавычках;
  - очень длинное описание обрезать нельзя, оно подставляется целиком;
  - текст пользователя вставляется как данные в отдельный блок, чтобы он не нарушал структуру промта;
  - папка с таким `id` уже существует: промт требует выбрать другое имя и не перезаписывать чужие виджеты.
- Версия SDK в промте всегда равна версии установленного приложения.

### Идентификаторы и версионирование

- Bundle ID: `io.github.aloesc.macoswidgets`.
- Версии приложения и SDK по SemVer (MAJOR.MINOR.PATCH). Тег релиза `vX.Y.Z` запускает сборку `.dmg`.
- В `manifest.json` виджета есть поле `sdk` с версией SDK, под которую он написан. Совместимость: тот же MAJOR и не выше установленного MINOR, иначе виджет не загружается и в консоли выводится причина. Ломающие изменения SDK возможны только при повышении MAJOR.
- Версия виджета (`version` в манифесте) тоже SemVer.

- Xcode-проект плюс SwiftPM-модули.
- GitHub Actions на `macos-26`: по тегу собирается universal `.dmg` (create-dmg) и публикуется в Releases.
- Подпись ad-hoc. Нотаризации и Developer ID нет.

## Крайние случаи и обработка ошибок

- **Исключение или зависание JS.** Таймаут на `render` около 100 мс, при превышении или исключении плашка «виджет упал» с кнопкой перезапуска и ссылкой на лог.
- **Нет сети или недоступен Open-Meteo.** Показывается последнее удачное значение с пометкой «устарело».
- **Некорректный манифест.** Виджет не загружается, причина видна в консоли ошибок. Приложение не падает.
- **Запрос вне permissions.** Вызов отклоняется, в консоль пишется понятная ошибка.
- **Метрика недоступна (`null`).** Виджет обязан обрабатывать это. Встроенные виджеты показывают «—».
- **Отключение монитора или смена разрешения.** Перенос виджета на главный монитор и возврат при подключении.
- **Сон и пробуждение.** Опрос ставится на паузу при сне экрана и скрытии виджета, после пробуждения возобновляется.
- **Часовые пояса и локаль.** Часы и погода используют системную локаль и часовой пояс, либо заданный в настройках.
- **Повреждённый конфиг.** Резервная копия повреждённого файла и запуск с настройками по умолчанию.
- **Правка файлов виджета при работе.** Hot reload пересоздаёт JSContext, состояние сбрасывается.

## Риски и меры

- **Запуск стороннего кода.** Песочница JSC без файлов, сети и shell, явные permissions, allowlist доменов. Остаточный риск: виджет с `network` может отправлять данные наружу на разрешённые домены, поэтому они видны в диалоге установки.
- **Нет подписи.** Gatekeeper блокирует первый запуск. Мера: инструкция в README. Риск для распространения принят.
- **Приватные API JavaScriptCore.** Подтверждено спайком: ES-модули работают, но `JSScript`, `JSModuleLoaderDelegate` и `JSContextGroupSetExecutionTimeLimit` не входят в публичный SDK и вызываются через Obj-C runtime и `dlsym`. Это приемлемо для распространения вне App Store (GPL, ad-hoc), но такие API могут измениться в новой macOS и не пройдут ревью App Store. Меры: понятная ошибка при отсутствии класса или селектора, тесты загрузки модулей в CI на каждой версии macOS. Запасной вариант (глобальное `widgee.*` и таймаут через отдельный процесс) остаётся в резерве.
- **Недокументированные API.** Температура, вентиляторы и GPU могут не работать на части машин. Мера: best-effort с `null`.
- **Производительность.** Опрос приостанавливается при скрытии, таймауты на `render`, общие лимиты. Проверяется замером в простое.
- **Изменения Liquid Glass API.** Всё изолировано в слое `Background`.
- **Топ процессов без root.** Список неполный. Это нужно явно указать в документации SDK.

## Принятые компромиссы

- Свои окна вместо WidgetKit: свобода кода и оформления в обмен на то, что виджеты не интегрированы в Notification Center.
- JS через JavaScriptCore вместо WebView: нативный вид и экономия ресурсов, но нет DOM и веб-экосистемы.
- Декларативное дерево вместо canvas: проще оформление в стиле Apple, меньше гибкости.
- Без подписи вместо платного аккаунта: бесплатно, но хуже первый запуск.
- Ручная проверка обновлений вместо Sparkle: простота и надёжность без подписи.

## Допущения (решено за пользователя)

- Минимум macOS 26 в MVP. Это нужно для нативного Liquid Glass. Слой фона изолирован, поддержка macOS 14+ закладывается архитектурой, но не входит в MVP (решение пользователя).
- Лёгкие границы: интерактивность и Stage Manager не входят в MVP.
- Метрики температуры, вентиляторов и GPU имеют статус experimental.
- Lock screen и Stage Manager не поддерживаются, так как нет публичного API.
- Название приложения: Widgee (выбрано пользователем).
- Галерея показывает только реализованные виджеты. Категории с макета (Календарь, Фото и т. д.) в MVP не входят.

## Эксплуатация и наблюдаемость

- Логирование через `os.Logger` с подсистемой приложения. Ошибки виджетов также пишутся в окно консоли.
- Окно консоли показывает ошибки загрузки, исключения JS и отклонённые вызовы.
- Версия приложения и ссылка на Releases видны в меню.
- Окно «О Widgee» (пункт в меню): иконка, версия, лицензия GPL-3.0, кнопка «Поддержать разработчика» со ссылкой https://donatty.com/aloescc (то же в README и в меню menu bar). Ссылка хранится в одной константе.
- Телеметрия не собирается.
- Откат: пользователь ставит предыдущий `.dmg` из Releases.

## План проверки и критерии приёмки

Тесты:
- Юнит-тесты ядра: парсинг манифеста, проверка permissions, allowlist доменов, кольцевой буфер метрик, сборщики метрик (границы значений), сохранение и восстановление позиций.
- Тесты хоста: таймаут и исключение в `render` не затрагивают другие виджеты, hot reload пересоздаёт контекст.
- Снапшот-тесты рендера компонентов для основных размеров.
- CI: сборка и тесты на `macos-26`, сборка `.dmg` по тегу.

Критерии приёмки:
1. `.dmg` собирается в CI и устанавливается на чистой macOS 26.
2. Три встроенных виджета добавляются, перемещаются, меняют размер и настройки фона. Все четыре режима фона работают.
3. Сторонний виджет из шаблона загружается, hot reload работает, ошибки видны в консоли.
4. Виджет без permission `network` не может выполнить запрос.
5. Виджет с бесконечным циклом не блокирует остальные и показывает плашку сбоя.
6. С тремя виджетами в простое приложение потребляет меньше 1% CPU и около 100 MB RAM (замер вручную).
7. При отключении монитора виджеты переезжают на главный и возвращаются при подключении.
8. Недоступная метрика (`null`) не ломает встроенные виджеты.
9. Промт из вкладки «Создать виджет» содержит актуальные путь, версию SDK и описание пользователя. Эталонный ИИ-агент, получив только этот промт, создаёт виджет, который загружается без ошибок и отображается в галерее (проверка вручную на 2–3 запросах).

## Этапы реализации

1. Каркас: Xcode-проект, SwiftPM-модули, menu bar, окно виджета на уровне рабочего стола.
2. `WidgetHost` и `Renderer`: JSContext, манифест, дерево компонентов, базовые компоненты.
3. Слой `Background` с протоколом и Liquid Glass, режимы фона, панель настроек.
4. `Metrics` и подписки (`system`, `timer`, `http` в `sources`), компоненты баров и графиков.
5. Встроенные виджеты: часы, системный монитор, погода (`useFetch`, песочница, permissions).
6. Режим редактирования, мультимонитор, сохранение конфигурации.
7. Тулинг авторов: hot reload, консоль, `.d.ts`, шаблон, импорт `.widget`, вкладка «Создать виджет» с генератором промта для ИИ-агента.
8. Устойчивость: таймауты, плашка сбоя, замер ресурсов.
9. CI, `.dmg`, README с инструкцией запуска без подписи, проверка обновлений через GitHub Releases.

После MVP: fallback для macOS 14+, каталог виджетов, интерактивность, локализация, подпись и нотаризация.
